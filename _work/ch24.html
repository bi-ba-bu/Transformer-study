把零件装起来：一次完整前向

案例走到哪了 所有零件都齐了。输入「小猫 追」，经过 embedding、Q/K/V、注意力、FFN， 最后得到 [2,V] 的概率表。位置 1 上，「老鼠」拿到 0.62，排第一。
说人话 这一步不再讲新零件，而是把前面的东西按顺序接起来： 文字变 ID，ID 变向量，向量算注意力，注意力结果再过 FFN， 最后乘一个“词表矩阵”，得到每个候选词的概率。
这一章要解决什么 把 29 章的知识装成一条流水线，算清每一步的张量形状，并知道最后的概率是怎么来的。
一句话进去，下一个词的概率出来
Block 层数

七步流水线

步骤做什么形状
1. Tokenize「小猫 追」→ 两个 ID[2]
2. Embedding查表，每个 ID 变 4 维向量[2] → [2,4]
3. + 位置编码加上“第 0 位 / 第 1 位”[2,4]
4. Block ×NLN → 注意力 → 残差 → LN → FFN → 残差[2,4]
5. 最终 LayerNorm收尾归一化[2,4]
6. LM Head乘 [4,V]，映射到词表[2,4] → [2,V]
7. Softmax每个位置变成概率分布[2,V]

训练时用完整的 7 个 token，形状是 [7,4]； 推理产品只输入前两个 token，形状是 [2,4]。 流程一模一样，只是 n 不同。

案例的形状账本

小猫 追
→ ID: [12, 88]　　　　　　　// [2]
→ 词向量 X: [2, 4]　　　　　 // 2 个 token，每个 4 维
→ Q/K/V: 各 [2, 4]
→ 分数 Q·Kᵀ: [2, 2]
→ softmax 权重: [2, 2]　　　 // 每行和为 1
→ 加权 V: [2, 4]
→ FFN + 残差: [2, 4]
→ LM Head: [2, V]　　　　　 // V = 50000
→ softmax: [2, V]

位置 1（「追」之后）的概率：
老鼠 0.62　小猫 0.18　饿了 0.10　其他 …

为什么取位置 1？因为输入是「小猫 追」，我们要预测「追」后面的词。 位置 0 的「小猫」预测的是「追」，不是产品这一步要的答案。

参数账：换成真实规模

设 d=768、V=50000、N=12：

每层注意力：4d² = 4×768² ≈ 2.36M
每层 FFN：8d² = 8×768² ≈ 4.72M
每层合计：12d² ≈ 7.08M

12 层：12×7.08M ≈ 85M
Embedding：50000×768 ≈ 38.4M
总计：85M + 38.4M ≈ 123M

GPT-2 small 是 124M，用的正是 d=768、N=12、V=50257。 手算结果几乎完全吻合。

形状账本 整个过程中，序列维 n 和特征维 d 一直是 [n,d]， 只有最后的 LM Head 才变成 [n,V]。 中间的 [n,n] 注意力矩阵是临时结果： 训练时反向传播还要用它，推理时不需要长期保存。
常见误解：参数量等于能力 参数量只决定容量上限，不决定实际能力。数据质量、训练方法、推理策略同样关键。 同样 7B 参数，层数深、d 小，和层数浅、d 大，效果也可能差很多。
