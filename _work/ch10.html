温度：生成时的“犹豫程度”旋钮

案例走到哪了 输入法已经算出候选概率：老鼠 0.62、小猫 0.18、饿了 0.10。 这一章调温度 T：想让输入法更果断，就把 T 调小；想让它偶尔给点意外，就把 T 调大。
说人话 温度不改变模型“觉得谁更对”，只改变它“敢不敢冒险”。 T 小，它更愿意只押第一名；T 大，它更愿意把机会分给后面的候选。 写代码时调小，日常聊天时调大；它不增加知识，只改变选词的胆量。
这一章要解决什么 搞懂温度 T 在 softmax 里到底改了什么，以及为什么同一个模型有时死板、有时发散。

公式只多了一个 T

softmax(zᵢ/T) = e^(zᵢ/T) / Σⱼ e^(zⱼ/T)

就是在取指数之前，把每个分数除以 T。两个分数的差距从 z₁ − z₂ 变成 (z₁ − z₂)/T：

  • T < 1：差距被放大，分布更尖锐，更接近“只选一个”。
  • T = 1：原样，训练时的标准设置。
  • T > 1：差距被压缩，分布更平均，更愿意尝试后面的词。

严格说，T = 0 不能直接代入公式（会除以 0）。 我们说的是 T 趋近 0 的极限：最大值那一项吞掉全部权重，退化成贪心选择。

温度 T 抬高"猫"的分数

手算一遍

用三个候选的分数 [2, 1, 0]，比较 T = 1 和 T = 0.5：

// T = 1
e²=7.389　e¹=2.718　e⁰=1　总和=11.107
概率 = [66.5%, 24.5%, 9.0%]

// T = 0.5（每个分数除以 0.5，等于乘 2）
e⁴=54.598　e²=7.389　e⁰=1　总和=62.987
概率 = [86.7%, 11.7%, 1.6%]

T 从 1 降到 0.5，第一名从 66.5% 涨到 86.7%。模型并没有“更聪明”， 只是更不愿意分机会给后面的候选。

实际怎么用

场景常用温度原因
训练1.0标准设置
写代码 / 做数学题0 ~ 0.3要确定性
日常对话0.6 ~ 0.8有变化但不胡说
写诗 / 头脑风暴1.0 ~ 1.3要发散
温度不是越高越好 太高会让模型输出近乎随机，句子不通顺；太低会让它每次都选同一个词， 连续生成时容易复读。温度调的是“冒险程度”，不是“知识多少”。

还有一个词叫 argmax：它不返回最大值本身， 而是返回最大值的位置。argmax([3,7,2]) = 1。 每次严格取 argmax，就是贪心解码；按温度采样，则是另一套策略。

一句话记住 温度 T 在 softmax 之前除一下：T 小更确定，T 大更随机。 T = 1 是训练默认值，T = 0 只是极限，不是能直接代入的数。
