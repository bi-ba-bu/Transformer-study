从文字到向量：按 ID 取一行

案例走到哪了 第 10 章调完温度，生成候选时仍要先拿到词向量。 这一章把「老鼠」的 ID 42 查成 [0.8, 0.2, 0.9, 0.1]；「它」后面要比较的候选，都从这张表出发。
说人话 输入法拿到的是编号，不是汉字。它按编号去一张表里取对应的一行，把「老鼠」变成四个数。后面所有计算都只碰这四个数。查表就是“按 ID 取行”，表格里的数会随着训练更新。 真实词表有几万行，查表的动作一样，只是表更长。
这一章要解决什么 看清文字变成向量的路径：分词 → ID → 查表 → 4 维向量。 同时把一个容易混的点说清：one-hot 乘 embedding 只是解释用的等价写法，实际实现直接按 ID 取行。

第一步：分词，再编号

案例句子被切成 7 个 token。每个 token 在词表里有一个整数 ID：

小猫 12　追 88　老鼠 42　，3　因为 77　它 9　饿了 105

「小猫追老鼠」→ [小猫] [追] [老鼠]
→ ID: [12, 88, 42]

ID 是行号，不是有大小含义的数。42 不比 9 “大”，就像 42 号柜子不比 9 号柜子更贵。 模型只认整数，所以这一步先把汉字换成编号。

第二步：one-hot 只是解释工具

one-hot 是“长度等于词表大小、只有 ID 那一格是 1”的向量。 对这张 7 行迷你表，「老鼠」的 one-hot 是 [0,0,1,0,0,0,0]。

它能说明“按 ID 取一行”这件事，但真实实现不会构造几万维的 one-hot。 直接拿 ID 当数组下标取行，省内存，也更快。

先把边界说清 one-hot 是数学上的等价写法，不是工程里的实际步骤。保留它，是为了看清 embedding 表是一个可训练的矩阵。

为什么不能直接拿 one-hot 进注意力

任意两个不同词的 one-hot，点积都是 0。第 06 章说过，点积为 0 表示两个方向没有重合。 于是「猫」和「狗」、「猫」和「石头」在模型眼里一样远。

one-hot 也不带语义信息。它只是身份标签，回答“你是几号”，不回答“你像谁”。 注意力要算“谁跟谁相关”，需要的是后者。

one-hotembedding
长度词表大小（几万）模型维度（案例里是 4）
数值含义只是编号，大小无意义每一维是一个学到的特征刻度
任意两词点积恒为 0可大可小可负，带相似度
是否可训练固定，没有参数是参数，跟着梯度更新

第三步：查表 = 矩阵乘法（等价写法）

E 是一张 [行数, 4] 的表，每一行是一个词的 4 维向量。 one-hot 乘 E 时，只有那个 1 对应的行被留下：

[0, 0, 1, 0, 0, 0, 0] × E[7, 4] = E 的第 2 行

因为其余位置都是 0，相乘相加之后只剩一行。 所以“查表”在数学上等价于“乘一个 one-hot 向量”。

实际代码走的是“按 ID 取行”，不会真的做这次乘法。 这个等价关系真正有用的地方，是说明 E 和 W_Q 一样，是可训练参数。

案例：老鼠 ID 42 → [0.8, 0.2, 0.9, 0.1]

这张迷你表只保留句子里的 7 个 token，每行 4 维：

迷你行号tokenID向量
0小猫12[1.0, 0.0, 0.2, 0.0]
1追88[0.0, 1.0, 0.0, 0.0]
2老鼠42[0.8, 0.2, 0.9, 0.1]
3，3[0.0, 0.0, 0.1, 0.0]
4因为77[0.0, 0.0, 0.0, 1.0]
5它9[0.7, 0.1, 0.8, 0.2]
6饿了105[0.0, 0.6, 0.0, 0.9]

ID 42 是它在完整词表里的行号，真实实现直接取 E[42]。 这张 7 行迷你表是为了手算，把用到的 7 个词重新排在 0 到 6 行，「老鼠」落在第 2 行；下面的 one-hot 也按这张迷你表来写。

老鼠（ID 42，迷你表第 2 行）
= [0.8, 0.2, 0.9, 0.1]

「它」要预测下一个词时，候选「老鼠」就从这一行出发；「小猫」从 [1.0, 0, 0.2, 0] 出发。 第 12 章会解释这些行为什么能比较远近。

词表 → one-hot → 乘 embedding 矩阵 → 取出向量
选一个词

手算一遍：one-hot 怎样只留下第 2 行

老鼠的 one-hot = [0, 0, 1, 0, 0, 0, 0]

0×row0 + 0×row1 + 1×row2 + 0×row3 + 0×row4 + 0×row5 + 0×row6
= 1 × [0.8, 0.2, 0.9, 0.1]
= [0.8, 0.2, 0.9, 0.1]　← 正好是 E 的第 2 行

真实词表有几万行时，one-hot 会有几万维，里面只有一个 1。 这个写法只适合解释；实现里一步 E[42] 就取到了同一行（迷你表里是第 2 行）。

回收：储物柜

ID 是柜号，E 是整面柜子，查表就是按柜号取件。 one-hot 像一张“只有对应柜子亮灯”的取件单：能解释取到了哪一格，但实际取件不需要打印整张单子。

一句话记住 文字 → token → ID → 按 ID 取 E 的一行 → 4 维向量。 “查表 = 乘 one-hot”是等价解释，实际实现直接按 ID 取行。
