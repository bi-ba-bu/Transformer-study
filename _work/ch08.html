矩阵乘法与转置：49 个分数一次算完

案例走到哪了 第 07 章把 7 个词变成了 Q[7,4]。这一章把 K[7,4] 竖成 Kᵀ[4,7]，做 Q[7,4] × Kᵀ[4,7] → [7,7]。 「它」看「老鼠」那一格是 2×1 + 0×0 + 4×1 + 0×0 = 6。
说人话 输入法要让 7 个词互相打分，一共 7×7 = 49 个分数。Q 的第 i 行是词 i 的提问，K 的第 j 行是词 j 的自我介绍。把 K 竖成列，两个长度为 4 的清单才能逐项对齐做点积。转置就是这次“竖起来”的动作。 结果是一张 7×7 的表，第 i 行就是词 i 的打分单。
这一章要解决什么 看清 Q·Kᵀ 里的 ᵀ 为什么存在、形状怎么从 [7,4] 和 [4,7] 得到 [7,7]。 结论只有一句：转置是把 K 的行变成列，好让词 i 的 Q 和词 j 的 K 对齐。

先把形状读顺

[7,4] 读作“7 行 4 列”。在这份教程里，行是词，列是特征。 所以 Q[7,4] 是 7 个词、每个词 4 维；Kᵀ[4,7] 是 4 行、7 列。

矩阵乘法有一条硬规则：左边列数要等于右边行数。 中间那个数会被加总掉，所以不会出现在结果形状里。

[7, 4] × [4, 7] → [7, 7]
// 中间的 4 对上；结果是 7 行 7 列

矩阵乘法 = 一批点积

结果里第 i 行第 j 列的数，等于左边第 i 行和右边第 j 列的点积。 这不是新运算，就是第 06 章的点积排成了一张表。

C[i][j] = (A 的第 i 行) · (B 的第 j 列)

放到案例里：[7,7] 的每一格，都是“词 i 的 Q”和“词 j 的 K”的点积。 第 i 行就是词 i 对 7 个词的打分表。

转置：把 K 的行变成列

K 原本是 7 行，每行一个词的 4 维 Key。转置不改变数，只改变摆放： 第 j 行竖起来，变成 Kᵀ 的第 j 列。

K 的第 0 行：小猫 [1, 0, 0, 0]
K 的第 2 行：老鼠 [1, 0, 1, 0]

Kᵀ 的第 0 列：小猫 [1, 0, 0, 0]
Kᵀ 的第 2 列：老鼠 [1, 0, 1, 0]

形状：[7, 4] → [4, 7]

不转置会怎样？[7,4] × [7,4] 本身就不满足“左列 = 右行”。 就算维度凑巧都是 7，Q 的第 i 行配到的也是 K 的第 i 列，也就是“第 i 个特征在 7 个词上的取值”，不是“词 i 的 K”。

所以转置不是为了省算力，也不是某种优化技巧。 转置之后，K 的第 j 行变成第 j 列，Q 的第 i 行才能和词 j 的 K 对齐。 它解决的是配对方向：要让 7 个 Q 和 7 个 K 两两相遇，其中一个得竖过来。

形状账本

这三行是后面所有公式的骨架。读的时候把“行”换成“词”，“列”换成“特征”。

X [7, 4] × W [4, d'] → [7, d']
Q [7, 4] × Kᵀ [4, 7] → [7, 7]
A [7, 7] × V [7, 4] → [7, 4]
式子人话词数
X·W7 个词，每个词从 4 维换算成 d' 维还是 7 个
Q·Kᵀ7 个词两两打分，得到 49 个分数变成“词×词”
A·V按权重把 7 个词混合成 7 个新词回到 7 个

进出都是 7 个词、4 维，所以同一个块可以原样叠很多层。 形状不变，是 Transformer 能堆深的工程前提。

两个常见误解 ① 矩阵乘法通常不满足交换律：A·B 和 B·A 往往不同，甚至只有一边能算。它对应“先做 B 再做 A”，顺序换了，结果就变。 ② 转置不是可选的装饰。没有它，配到的是同一行，算不出跨词关系。

回收：竖名单

转置像把一张按“人”写的名单竖过来，改成按“项目”排。 名单上的数一个没变，但原来对不上的两列，现在可以逐项对齐了。

一句话记住 Q[7,4] × Kᵀ[4,7] → [7,7]。转置只是把 K 的行变成列，让每一格都是“词 i 的 Q”和“词 j 的 K”的点积。
