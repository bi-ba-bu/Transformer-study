softmax：把分数变成分配比例

案例走到哪了 上一章算出了「它」对 7 个词的分数： [1, 0, 3, 0, 0, 0.6, 0]。 这一章把它们变成加起来等于 1 的权重，结果「老鼠」拿到 70.2%。
说人话 分数可以是负数，也可以很大，没法直接当“取走多少内容”的份数。 softmax 做三件事：先把每个分数变成正数，再算总和，最后按比例分这 100%。 分高的拿得多，但所有人加起来只能拿 100%。
这一章要解决什么 搞懂 softmax 具体怎么算，以及为什么注意力的权重必须“全是正数、加起来等于 1”。

为什么非要做这一步

注意力下一步要按权重去“吸收”别的词的 V。权重如果是负数，就成了“吸收 −5 份”； 如果总分不是 1，吸收的总量又不确定。softmax 就是在解决这两个问题。

要求为什么谁负责
全是正数不能“吸收负数份”取 eˣ
总和为 1总量固定，比例才有意义除以总和
保持大小顺序分高的还应该拿得多eˣ 单调递增

三步，拿案例算一遍

原始分数（logits）是「它」这一行：

z = [1, 0, 3, 0, 0, 0.6, 0]

① 取指数
e¹ = 2.718　e⁰ = 1　e³ = 20.086　e⁰·⁶ = 1.822
→ [2.718, 1, 20.086, 1, 1, 1.822, 1]

② 求和
2.718 + 1 + 20.086 + 1 + 1 + 1.822 + 1 = 28.626

③ 每个除以总和
[0.095, 0.035, 0.702, 0.035, 0.035, 0.064, 0.035]

读法：「它」把 70.2% 的注意力给了「老鼠」，9.5% 给「小猫」，6.4% 留给自己。 这三个数加起来，再加上标点和虚词，正好是 100%。

exp → 求和 → 相除，三步逐格演算

为什么用 eˣ，不用绝对值或平方

方案变正？保序？问题
|x|✓✗把 −5 和 +5 变成同一个数，正负信息丢了
x²✓✗同样丢符号，还会把大数放得过大
x + C✓✓C 没有天然答案；太小负数还在，太大比例失真
eˣ✓✓同时满足，还能把加法差距翻译成倍数差距

取指数还有一个副作用：拉开差距。 两个分数差 1，取指数后变成约 2.72 倍；差 3，变成约 20 倍。 所以分数尺度太大时，softmax 会变得非常尖锐，几乎只选一个词。 第 18 章的 /√d 就是来管这件事的。

给矩阵做 softmax：一行一行来

分数矩阵是 7×7。softmax 对每一行单独做： 第 i 行代表第 i 个词怎么分配自己的 100% 注意力，和其他行无关。

第 5 行（它）：[1, 0, 3, 0, 0, 0.6, 0]
→ [0.095, 0.035, 0.702, 0.035, 0.035, 0.064, 0.035]
这一行加起来 = 1 ✓
一句话记住 softmax 不是“变成概率”这么玄，它就是把任意分数变成总和为 1 的分配比例。 一行里此消彼长：一个词多拿，其他词就必然少拿。
实现时最容易错的地方 按行归一化，代码里要沿最后一维做：PyTorch 写 softmax(x, dim=-1)。 写成 dim=-2 就是按列归一化，形状不报错、数字也不报错， 但训练会莫名其妙不收敛。
关于 e^−1000 数学上它永远大于 0；但浮点数会下溢成 0。 所以实际代码先减去最大值再取指数，数学上等价，数值上安全。
这一章读完后，请自测 ① 为什么不能用绝对值代替 exp？（会把 −5 和 +5 混成一样） ② [0,0,0] 经过 softmax 得到什么？（[1/3,1/3,1/3]） ③ 一行是 [0.7,0.3]，第一个提高，第二个会怎样？（必然下降）
